How do you troubleshoot if your instance is unhealthy in a target group? 
- Is your instance in the running state?
- Verify whether the instance security group's required port is open or not.
- Verify the health check path you configured. Make sure your path exists in your EC2 instance.
- Verify whether the application running inside your EC2 instance is working on that port or not.
- Verify your application's running status. Is our application really running or not?
- Make sure your load balancer is added with all subnets.

Q: what algorithm does an application load balancer use? Can we adjust these algorithms? 
Ans: by default the application load balancer uses the nested round-robin algorithm. Traffic routes as a cycle. 


Round robin : It routes requests evenly across healthy targets, in a sequential order. This is commonly used when the received requests are similar in complexity and the targets are similar in processing capability.

Least outstanding requests : Least outstanding requests routes requests to the target with the lowest number of in progress tasks. This is commonly used when the received requests vary in complexity or the targets vary in processing capability.

Weighted Random : uses anomaly mitigation to identify HTTP status codes and connection errors, then routes the traffic intelligently.

Availability Zone distribution : 

Balanced best effort : if instance launch fails in one availability zone, the auto scaling group will attempt to launch an instance in another healthy availability zone. 

Balanced Only : if launch fails in one availability zone, the auto scaling group will continue to launch instances in the same availability zone even if its status is unhealthy.
